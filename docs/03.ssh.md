# 3. SSH

SSH (*secure shell*) opens a shell on another computer over the network. You
type on your laptop but the commands run on the server and the output comes back.

The connection is encrypted, which means only the client and the server can
read the intercommunication.

ssh should be pre-installed on both Mac and Windows 11.

## Log in

```console
$ ssh anna@server.example.org
anna@server:~$
```

The prompt changes. That is how you know where you are. `exit` (or `Ctrl+D`) returns
you to your own machine.

Logging in with an SSH key instead of a password is described in
[5. Git](05.git.md#ssh-keys) — the same kind of key works for both.

The first time you connect it asks about a fingerprint. Type `yes`. It is
recording the server's identity in `~/.ssh/known_hosts` so it can warn you if
the server is ever swapped out.

## Copying files

`scp` is a good tool for moving a small number of files.
`rsync` (not pre-installed on Windows) is the better tool for anything large or
repeated: interrupt it, run it again, and it continues where it stopped.

Run these **on your laptop**, not while logged in to the server:
```console
$ scp report.pdf anna@server.example.org:~/       # laptop -> server
$ scp anna@server.example.org:~/results.csv ./    # server -> laptop
$ rsync -av data/ anna@server.example.org:~/data/ # a directory, skipping what is already there
```

## What happens if the connection is broken?

Closing the terminal, losing wifi or shutting your laptop kills the connection
— and anything that was running in it dies too. For long jobs you need `tmux`
or `nohup`, which come later.
