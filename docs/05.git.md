# 5. Git

[git - official documentation](https://git-scm.com/)

[git](https://en.wikipedia.org/wiki/Git) is a distributed version control system
originally created by Linus Torvalds for administering the code for the Linux
kernel.

It is a great way to keep your source files in order!

## Initial configuration

Git puts your name on every commit, so tell it who you are:

```console
$ git config --global user.name "Anna Andersson"
$ git config --global user.email "anna@example.org"
```

## Starting a repo

Either turn an existing directory into one:

```console
$ cd ~/projects/analysis
$ git init
```

or take a copy of one that already exists:

```console
$ git clone git@github.com:anna/analysis.git
$ cd analysis
```

## The everyday loop

```console
$ git status                    # what has changed - use this constantly
$ git add script.py             # stage a file for the next commit
$ git add .                     # stage everything changed here
$ git commit -m "Fix off-by-one in the window size"
$ git log --oneline             # the history, one line per commit
$ git diff                      # what have I changed but not staged
```

`git status` is the command you run when you are not sure what is going on.
It usually also suggests what to type next.

Working with a remote:

```console
$ git push          # send your commits to GitHub
$ git pull          # fetch and apply other people's commits
```

## What not to commit

Commit the things you write. Do not commit things that can be regenerated,
things that are large, and things that are secret:

- data sets and model checkpoints — Git stores every version forever, and a
  repo with a 2 GB file in its history stays 2 GB even after you delete it
- results, figures and logs that a script produces
- virtual environments (`.venv/`, `__pycache__/`)
- passwords, API keys, tokens

List them in a file called `.gitignore` in the top of the repo:

```
.venv/
__pycache__/
results/
*.log
```

`.gitignore` itself *should* be committed. Small input files are fine to
commit — this repo tracks `data/sample.txt` on purpose — but a corpus or a
model checkpoint is not.

If a secret does get committed, deleting it in a later commit is not enough —
it is still in the history. Change the password.
