# 7. Long-running jobs: tmux and nohup

A script that takes eight hours cannot be run the way you run `ls`. If the
connection drops, the terminal closes, or you shut your laptop, the job dies
with it.

Two tools fix this. You do not need to master either one. You need to start a
job, walk away, and find it again tomorrow.

| | Use it when |
|---|---|
| **tmux** | You want to come back, look at the output, and keep working. Default choice. |
| **nohup** | One command, fire and forget, output goes to a log file. |

## tmux
-
### The short version

```console
anna@server:~$ tmux new -s work      # start
                                     # run your job, then Ctrl+B d
anna@server:~$ tmux ls               # what is running
anna@server:~$ tmux attach -t work   # come back
```

### The long version

Think of it as a terminal that keeps running after you leave.

Start a named session:

```console
anna@server:~$ tmux new -s training
```

The screen clears and you get a fresh prompt with a status bar at the bottom.
This is a normal shell — start your job in it:

```console
anna@server:~$ source my-venv/bin/activate
(my-venv) anna@server:~$ python3 train.py
```

Now **detach**: press `Ctrl+B`, let go, then press `d`.

You are back at your ordinary prompt and the job is still running. You can log
out, close the laptop, and go home.

### Getting back

Log in again and ask what is running:

```console
anna@server:~$ tmux ls
training: 1 windows (created Mon Sep  8 09:14:03 2026)
```

Attach to it:

```console
anna@server:~$ tmux attach -t training
```

You are looking at the same screen you left, with the output that accumulated
while you were away.

### The only keys you need

Every tmux command starts with `Ctrl+B`, released, *then* the next key. The
letters are lower case: `Ctrl+B` `D` is a different command from `Ctrl+B` `d`.

| Keys | Does |
|---|---|
| `Ctrl+B` `d` | Detach — leave it running |
| `Ctrl+B` `c` | New window inside the session |
| `Ctrl+B` `n` | Next window |
| `Ctrl+B` `[` | Scroll back through output — `q` to stop scrolling |

Scrolling needs `Ctrl+B` `[` because tmux is drawing the screen itself, so your
mouse wheel and scrollbar may not work as usual.

### Finishing

When the job is done and you no longer need the session, `exit` inside it
closes it. From outside:

```console
anna@server:~$ tmux kill-session -t training
```

A forgotten session runs forever and keeps using memory. Check `tmux ls`
occasionally.

Some older servers have `screen` instead of `tmux`. Same idea, different keys:
`screen -S name`, detach with `Ctrl+A` `d`, return with `screen -r name`.

## nohup

For a single command you do not need to watch, `nohup` is quicker than tmux:

```console
anna@server:~$ nohup python3 train.py > train.log 2>&1 &
[1] 48213
```

Piece by piece:

| Part | Does |
|---|---|
| `nohup` | Ignore the hangup signal sent when your connection closes |
| `> train.log` | Send normal output to a file instead of the screen |
| `2>&1` | Send error messages to the same file |
| `&` | Run in the background, give the prompt back |

`48213` is the process ID (PID). Note it down; it is how you refer to the job
later.

Without the redirection the output goes to a file called `nohup.out`, which is
fine until you start a second job in the same directory and both write to it.
Name the log yourself.

### Getting back

There is no screen to return to — the log file *is* the job's output:

```console
anna@server:~$ tail -f train.log     # follow it live, Ctrl+C to stop watching
anna@server:~$ tail -n 50 train.log  # just the last 50 lines
```

`Ctrl+C` here stops *watching*. It does not stop the job.

To check the job is still alive, and stop it if you want:

```console
anna@server:~$ pgrep -af train.py    # find it by name, with its PID
48213 python3 train.py
anna@server:~$ ps -u anna            # everything you are running
anna@server:~$ kill 48213            # ask it to stop
anna@server:~$ kill -9 48213         # make it stop, if it ignores the above
```
